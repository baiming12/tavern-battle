# 酒馆战斗插件 Demo v0.5.1

这是“剧情触发战斗 → 玩家亲自打完 → 把战斗事实交给 AI 小说化”方案的第一版独立战斗原型。

## 怎么运行

直接用浏览器打开 `index.html` 即可。它不依赖服务器、npm 或外部资源，因此手机和电脑都能离线试。

## v0.5.1 已实现

- 9×9 方格战场
- 真正的集气时间轴：所有单位同时积累行动条，先满者先行动
- ×1 / ×2 / ×4 时间轴速度
- 移动 + 朝向
- 一式 / 二式 / 绝式
- 轻功位移
- 心法 Buff
- 真气与技能 CD
- 防御

- 命中 / 闪避

- 全过程 Narrative Log
- 战斗结束后生成可直接给 AI 的 `<BATTLE_RESULT>` 战斗包

## 当前“已按公开资料确认”的逸剑规则

- 集气值是行动条，集气速率越高行动越快。
- 侧击：伤害 +15%。
- 背击：命中 +50%，伤害 +15%。
- 暴击：1.5 倍伤害。
- 四维公开攻略关系：
  - 1 力道 ≈ +2.5 攻击、+0.08 暴击
  - 1 根骨 ≈ +25 气血、+3 防御
  - 1 身法 ≈ +0.025 闪避，并影响行动/移动相关能力
  - 1 内功 ≈ +30 真气、+1.5 集气速率
- 公开攻略还给出：3 点集气速度约减少 0.01 秒行动间隔。
- 原作许多轻功/心法/增益会直接改变“当前集气值”或“集气速率”。

## 当前仍是占位/近似的部分

为了先把插件跑起来，以下规则暂时没有冒充原作精确公式：

- 最终伤害公式

代码中这些位置都单独标注，后续拿到更可靠数据后可以替换，不需要推翻 UI 或整体架构。

## 设计原则

> 小游戏决定事实，AI 决定表现。

底层日志只记录结构化事实，不把“武侠文案”写死。以后可针对角色/世界设置 narrative style，从而复用到修仙、西幻、现代、科幻等世界观。

## v0.5.1：玩家手动规划移动路线

普通移动不再“选择终点 → 自动走 BFS 最短路”。

现在流程为：

1. 点击【移动】进入路线规划。
2. 从角色当前位置开始，逐格点击上下左右相邻空格。
3. 棋盘会持续显示已经规划的路线以及第 1、2、3… 步。
4. 绿色格表示当前路线末端下一步可以前往的位置。
5. 点击已经规划过的旧路线格，会把路线回退到该步。
6. 也可以使用【撤销一步】或【清空路线】。
7. 点击【确认移动】后才真正执行整条路线、记录日志并决定最终朝向。
8. 点击【取消选择】则整条未确认路线作废，不消耗本回合移动。

移动日志保存完整实际路线，因此后续可以在每一个步进节点接入“每移动一格”“进入特定格”“经过地形”等 Event → Effect 效果。

### 当前路线限制

为了避免未来“每移动一格触发效果”被原地绕圈无限利用，v0.5.1 暂时不允许同一路线重复踩同一个格子。若后续确认《逸剑》原作允许重复经过同格，可单独放开。


## v0.5.2：移动力改为本回合资源

玩家普通移动不再采用“选择终点后自动寻路”，也不再需要先规划完整路线再确认。

现在的流程：

1. 角色获得行动时拥有普通移动力。
2. 点击【移动】后，只能点击角色上下左右相邻的绿色空格。
3. 每点击一次，角色立即实际移动 1 格并消耗 1 点移动力。
4. 只要还有剩余移动力，可以连续移动多次。
5. 可以中途退出移动模式、查看技能，再重新进入移动继续使用剩余移动力。
6. 在正式行动前可以【退一步】，也可以【悔棋】撤销本回合全部普通移动。
7. 攻击、防御、调息、心法等正式行动默认会结束本回合，因此行动后不能继续普通移动。
8. 技能可配置 `canMoveAfterAction: true`；这类技能结算后保留尚未使用的普通移动力，但不能再进行第二次正式行动。
9. Demo 中的「三式·横云」暂时带有 `canMoveAfterAction: true`，用于测试“攻击后移动”。

敌方 AI 仍保留 BFS 自动寻路；玩家移动则完全由逐格点击决定实际路线。

### 简单酒馆战斗触发格式

```text

场景=林间伏击
尺寸=9
我方=p1@2,7,N; p2@3,8,N
中立=
```

编辑器寻找：
`window.TavernBattleAIProvider.generate({kind,prompt,schema})`

## v0.8：触发型天赋正式运行 + 编辑器中英文显示

### 修复：AOE 点空地仍应触发 `attack_hit`
`attack_hit` 现在由**实际命中的每个单位**产生，而不是由玩家点击的技能中心格产生。

因此：
- 点击敌人作为中心，命中 → 触发；
- 点击空地作为中心，但范围覆盖并实际命中敌人 → 同样触发；
- 真正空放、范围内没有命中任何敌人 → 不触发。

攻击命中/暴击天赋默认 `triggerScope: once_per_action`，即一次范围技能打中多人时默认只触发一次。
编辑器可改为：
- `once_per_action`：每次技能/攻击至多1次；
- `per_target`：每个实际命中目标都可触发；
- `once_per_turn`：每回合至多1次；
- `per_event`：每次事件都触发。

### Event → Condition → Effect 已接入
已支持事件：
- battle_start
- turn_start / turn_end
- attack_hit / attack_crit
- damage_taken / hp_changed
- move_step
- defend / rest
- kill

已支持效果：
- modify_stat
- gain_gauge
- heal
- deal_damage
- apply_status
- grant_move
- refund_qi

`wind_after_strike / 乘隙而行` 现在会真的在命中后给予临时移动力，并允许本次正式攻击后继续移动。

### 编辑器语言
编辑器右上增加：
- 中文（默认）
- English

底层仍保存英文 ID，例如 `attack_hit / qiSpeed / once_per_action`；
切换语言只改变显示文字，不改变 JSON 和规则代码。


## v0.9：通用 Rule Engine + Buff / Debuff

v0.8 的“天赋事件引擎”已扩展为所有来源共用的规则引擎：

`Event → Condition → Effect → Duration`

规则来源现在包括：
- 技能 `skills[].rules`
- 装备 `equipment[].rules`
- 天赋（兼容旧 conditions/effects，同时支持 rules）
- Buff / Debuff `statuses[].rules`

### Buff / Debuff
合集新增 `statuses.json`。状态支持：
- buff / debuff
- 最大层数
- 刷新 / 叠层并刷新 / 替换层数
- 持续回合
- 可驱散标记
- 属性 modifiers
- 自己的 Event Rules

默认示例：
- 聚气：Buff，集气速率 +25%，3回合。
- 流血：Debuff，可叠3层；自身行动结束时每层受到28伤害。
- 破防：Debuff，防御 -20%，2回合。

### 技能 / 装备 / 天赋都能施加状态
编辑器里的技能和装备加入“通用规则”可视化区，可以选择事件、效果、目标、状态ID、层数。
天赋编辑器的 Effect 也支持 `apply_status / remove_status`。

Demo 示例：
- 二式·回风：实际命中目标后附加1层流血。
- 心法·聚气：使用技能时给自身聚气 Buff + 25集气。
- 练习铁剑：攻击暴击时 +10集气。

## v0.11：技能本体 Effect + 状态阈值完整可视化

### 技能本体 Effect
攻击类技能新增 `coreEffects`，可视化支持：
- damage：伤害；倍率、命中、暴击、障碍伤害；
- heal：治疗；固定值或百分比；
- apply_status：施加状态；层数、概率、是否要求本招实际命中；
- push：击退；
- pull：拉拽；
- move_self：施法者向技能落点方向位移。

本体 Effect 按列表顺序执行，可组合为：
`伤害 → 上状态 → 击退`

技能原来的 Event Rule 仍保留，适合“命中后获得集气”等事件型效果。

### 状态阈值
Buff/Debuff 的 threshold 现在拥有完整多 Effect 可视化编辑器。
达到阈值后可执行多个通用 Effect，并选择：
- 清空状态；
- 只消耗阈值层数。

默认「流血」示例：
- 最高3层；
- 每层行动结束受到28伤害；
- 达到3层额外受到60伤害；
- 消耗3层。

### AI 到底怎么使用技能？
这里明确分成两种 AI：

1. **生成 AI（SillyTavern 当前模型）**
   - 负责战斗开始前创建/补全角色、技能、装备、地图等数据；
   - 不参与战斗数值结算。

2. **战术 AI（插件本地 JS）**
   - 负责敌人每次行动时选技能、选落点、选移动位置；
   - 不请求 API，不消耗 Token；
   - 根据技能 `castMask / effectMask / coreEffects / 真气 / CD / 状态 / 位置` 自动评分；
   - 支持把 AOE 落点放在空地，只要这样能覆盖更多有效目标；
   - 会考虑预计伤害、击杀、背击/侧击、治疗、护盾、控制状态、位移、吸血、召唤等；
   - 如果当前位置不能形成好技能，会同时评估“移动到哪里以后最好出招”；
   - 没有合适攻击时可使用轻功接近，再不行则考虑心法、调息或防御。

### AI 使用权重
技能编辑器新增 `AI使用权重`：
- `1.0`：正常；
- `2.0`：AI明显更偏爱；
- `0.5`：保守使用；
- `0`：战术 AI 不主动使用。

这可以用来控制 Boss 的招牌技能，而不需要把技能逻辑写死在 AI 代码里。

战术评分过程不调用随机数；命中、暴击、状态概率等真正结算仍通过 Battle Seed RNG。
